## 🔴 Critical Gap: CSRF Token Missing in visited_links.js

**Affected:** JS-01, and indirectly the persistence half of GAD-01/GAD-02/GAD-03

### Root Cause

`visited_links.js` fires `$.post('/visited_links', { url: url })` with no CSRF token. In this Rails 8.1 app:

- `app/assets/javascripts/application.js` loads `rails-ujs` (not `jquery_ujs`)
- `rails-ujs` manages CSRF only for its own-initiated requests (data-remote links, Rails form submissions)
- `rails-ujs` does **not** call `$.ajaxSetup` or `$.ajaxPrefilter` — jQuery's `$.post` is outside its scope
- `ApplicationController` uses `protect_from_forgery with: :exception` (strictest mode)
- Result: production `$.post` → HTTP 422 `ActionController::InvalidAuthenticityToken` — **silent failure** (no `.fail` handler)

### Why Tests Missed It

- **Controller tests**: Rails integration test helpers auto-include CSRF tokens; do not simulate raw tokenless jQuery AJAX
- **Cucumber E2E**: Asserts optimistic `$(this).addClass('link--visited')` which fires **before** `$.post`; scenario never reloads the page to verify server-side persistence; CSRF failure is invisible

### Fix (minimal)

Add CSRF token injection for jQuery AJAX. Recommended approach — in `visited_links.js` directly:

```javascript
$.post('/visited_links', {
  url: url,
  authenticity_token: document.querySelector('meta[name="csrf-token"]').content
});
```

Or globally (preferred — covers other future jQuery AJAX calls):

```javascript
// In application.js or a new csrf_setup.js, after rails-ujs:
document.addEventListener('DOMContentLoaded', function() {
  var token = document.querySelector('meta[name="csrf-token"]');
  if (token) {
    $.ajaxSetup({ headers: { 'X-CSRF-Token': token.content } });
  }
});
```
