<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Controller → VisitedLink.urls_for | current_user is the trust anchor — fetches only the authenticated user's visited URLs |
| View → visited_link_class helper | url values come from server-side feed/API data, not from untrusted user input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-86-01 | Information Disclosure | @visited_urls exposes user's browsing history in controller scope | accept | @visited_urls is scoped to authenticated user via current_user; only rendered in that user's response; Devise gate enforced by ApplicationController before_action |
| T-86-02 | Spoofing | assign_visited_urls called for wrong user if current_user is spoofed | mitigate | current_user is set by Devise from session — not from params; no override possible at controller level |
| T-86-03 | Tampering | XSS via visited_link_class output in class attribute | accept | visited_link_class returns only the literal string "link--visited" or "" — no user-controlled data is interpolated into the class value |
| T-86-04 | Denial of Service | Large visited_links table causes slow urls_for query | accept | Personal-app scale; single user; urls_for is a single SELECT with user_id index (Phase 84 migration added index) |
| T-86-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — pure Rails controller/view/helper changes |
</threat_model>
