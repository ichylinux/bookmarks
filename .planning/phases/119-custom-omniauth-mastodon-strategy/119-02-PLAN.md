    - Override `request_phase` to call `register_application!` before `super`

      - `client_name`: application name (e.g. `Rails.application.class.module_parent_name` or `'Bookmarks'`)
      - `redirect_uris`: full callback URL from `callback_url` helper
      - `scopes`: `read` (sufficient for verify_credentials)
    - Parse response JSON; store `client_id` and `client_secret` in session keys above
    - On non-2xx response, `fail!(:invalid_credentials, ...)` with status/body snippet

    Do NOT implement composite uid `{instance}:{id}` — Phase 121 assembles that in `from_omniauth`. This phase sets `uid` to raw Mastodon account id string only.

| Strategy → Mastodon instance | Dynamic HTTP to user-chosen federated host; SSRF risk partially mitigated by Phase 120 domain validation |
| Mastodon API → auth hash | verify_credentials response is trusted for uid/info |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-119-04 | Tampering | Session client_id/secret | accept | Session-bound credentials are standard OAuth round-trip pattern; HTTPS to instance |
