<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → POST /visited_links | url param crosses from untrusted client to server |
| Controller → VisitedLink.record! | current_user.id is the trust anchor — never params[:user_id] |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-84-05 | Spoofing | POST /visited_links unauthenticated access | mitigate | authenticate_user! inherited from ApplicationController; Devise returns 401 automatically on unauthenticated requests |
| T-84-06 | Tampering | User A records visits attributed to User B | mitigate | user_id is always current_user.id inside create action — params[:url] is the only accepted param; user_id is never taken from params |
| T-84-07 | Tampering | CSRF on POST /visited_links | mitigate | protect_from_forgery with: :exception in ApplicationController; rails-ujs injects X-CSRF-Token into XHR automatically (Phase 87 will use $.post via rails-ujs) |
| T-84-08 | Denial of Service | Flood of POST requests growing visited_links table | accept | personal-app scale (single user); no rate limiting warranted at this scope |
| T-84-SC | Tampering | npm/pip/cargo installs | accept | no package installs in this phase — Rails/MySQL/Devise stack only |
</threat_model>
