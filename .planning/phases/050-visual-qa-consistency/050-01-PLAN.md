# Plan: 050-01 — Visual QA & Cross-theme Consistency Fixes

**Phase:** 50 — Visual QA & Cross-theme Consistency Fixes
**Requirements:** PREFS-01, PREFS-02, PREFS-03, CONS-01, CONS-02, CONS-03
**Status:** Ready

## Goal

CSS code review of preferences page and shared components across modern/classic/simple themes. Remove the redundant `.modern .preferences-table th` override. Add Minitest coverage for preferences page rendering across all 3 themes. Tri-suite gate.

## Tasks

### Task 050-01-01: CSS code review — preferences page

Read and review CSS for each theme on the preferences page:
- `preferences.css.scss` — base submit button (un-prefixed, applies to all)
- `themes/modern.css.scss` — modern submit button + `.modern .preferences-table th`
- `themes/classic.css.scss` — classic submit button
- `themes/simple.css.scss` — simple submit button

Check: all 3 themes have submit button styles (done by Q-09). Identify and document any remaining issues.

**Specific fix:** Remove the redundant `.modern .preferences-table th { text-align: right }` block from `themes/modern.css.scss` — the base rule in `common.css.scss` already handles this for all themes.

### Task 050-01-02: CSS code review — shared components

Review consistency of:
1. **Action links** (`.actions a`) — `common.css.scss` base + `.modern .actions a` override. Classic/simple use neutral grey — acceptable.
2. **Flash messages** — `common.css.scss` defines `.flash-notice` (green) and `.flash-alert` (red) — same across all themes — correct.
3. **Form controls** — modern has explicit styling; classic/simple use browser defaults — intentional.

Document findings in SUMMARY.md. Apply fixes only where a real inconsistency exists (expected: none beyond the preferences-table redundancy).

### Task 050-01-03: Add Minitest for preferences page cross-theme rendering

Extend test coverage to assert the preferences form renders correctly for all 3 themes:

**Test file:** `test/controllers/preferences_controller_test.rb` (extend existing)

**Test approach:** For each theme (modern, classic, simple):
- Set `user.preference.theme = '<theme>'` and save
- GET `/preferences` (authenticated)
- `assert_select 'form.preferences-form'`
- `assert_select 'table.preferences-table'`
- `assert_select 'input[type="submit"]'`

These assertions verify the form structure is intact regardless of theme — CSS visual correctness is confirmed by code review, not by DOM assertions.
