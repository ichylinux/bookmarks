## Overview

On mobile, only gadgets for the initially active column are loaded on page load; each other column's gadgets are loaded exactly once when first switched to — never re-fetching within the same page session. Desktop behavior is completely unchanged. Also extracted the note gadget from SSR into an AJAX-fetched fragment, removing two DB queries from every dashboard page load.

## Milestone Summary

**Key Accomplishments:**

1. Parse-time `window.portalLazy` coordinator with `register`/`loadColumn` API — desktop pass-through, mobile queue-and-drain, synchronous mark-before-fire, zero visible behavior change on desktop.
2. All 4 AJAX gadget partials (`_feed`, `_mastodon_account`, `_x_account`, `_calendar_gadget`) route through `portalLazy.register`; `activateColumn` drains each column on first visit; mobile lazy loading live.
3. Phase 77 bug fix: `register()` checks `loadedColumns[columnIndex]` before push — critical for PTM-fires-first ordering under Sprockets.
4. 9 contract tests for `portal_lazy.js` API; `activateColumn`→`loadColumn` integration assertion locked in test suite.
5. Removed two DB queries from every dashboard page load: `Note.new` and `notes.active.recent` moved to `NotesController#gadget` (GET /notes/gadget).
6. `note_gadget.js` refactored to `initNoteGadget()` factory + `noteGadgetLoaded` event — safely re-initializes handlers after AJAX injection.

**Key Decisions:**

- IIFE at parse time for coordinator (ordering guarantee under Sprockets)
- `portalLazy.register` checks `loadedColumns[columnIndex]` before push (Phase 77 bug fix — critical for PTM-fires-first race)
- `notesLoaded = true` set synchronously before `$.get` (IMPL-04 pattern extended to notes)
- `noteGadgetLoaded` custom event for post-AJAX JS re-init (clean decoupling)
- No preference guard in `NotesController#gadget` — panel omitted server-side when `use_note` is false

**Tech Debt:**

- TEST-02 partial: behavioral Cucumber scenario for single-column-load verification not added (static assertion used instead)
- Pre-existing: out-of-bounds column index not guarded at `portal_lazy.js` layer
- Pre-existing: `$('.gadgets').sortable()` has no mobile guard in `_dashboard.html.erb`
