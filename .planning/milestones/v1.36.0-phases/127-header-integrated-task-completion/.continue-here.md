## Root-cause hypothesis (investigate first, don't assume)

In `app/assets/javascripts/todos.js`:

- Selection toggle handler (lines 81–86) is delegated on `'li span:first-child'`; the highlight handler (88–92) calls `e.preventDefault(); e.stopPropagation();`. A plain click on the `<button class="todo-highlight-btn">` (a direct child of `<li>`, NOT inside the first span) should therefore **not** fire the selection handler. So simple event bubbling is probably NOT the cause.
- **Most likely cause:** `todos.toggle_highlight` (lines 110–120) does `$li.replaceWith(html)` on AJAX success. The server-rendered `_todo.html.erb` does **not** carry the `selected` class, so re-rendering a currently-selected row **drops its `.selected` state** (checkmark disappears) and, conversely, the header count is now stale. This is the "completion checkmark turns on/off when I click highlight" symptom.
  - Note: `toggle_highlight`'s `replaceWith` predates Phase 127, so this may be a **pre-existing** bug now made relevant because completion depends on preserved selection. Confirm by checking out before Phase 127 if needed, but fixing it is in-scope for Phase 127's gap closure regardless.

### Fix direction (for the gap plan)
In `todos.toggle_highlight` success callback, **preserve selection across the re-render**:
1. Capture whether `$li` had `.selected` before the AJAX call.
2. After `$li.replaceWith(html)`, re-apply `.selected` to the new `<li>` (and its `span:first-child`) if it was selected.
3. Call `todos._updateCompleteGroup(ol)` so the header count stays correct.
Alternatively, switch `toggle_highlight` to update only the highlight button/state in place rather than replacing the whole `<li>` (bigger change — prefer the preserve-and-reapply approach).

**Verify the fix** by reproducing in a browser: select a row → click its highlight → checkmark must remain; count must stay correct. Add this to Phase 128's Cucumber coverage if not already (selection survives highlight).
