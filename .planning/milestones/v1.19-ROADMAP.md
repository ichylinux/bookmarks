## Milestone Summary

**Key Decisions:**

- Faraday `:test` adapter retained for `XClient#fetch_following` and `MastodonClient#fetch_recent_status_previews` unit tests (both accept `connection:` injection)
- WebMock used for `XClient#fetch_recent_tweets` tests — the method builds its own Faraday connection and does not check `@forced_connection`, making `:test` injection impossible without a code change
- `WebMock.remove_request_stub` used in Cucumber After hooks (not `WebMock.reset!`) to avoid wiping the global slashdot fixture stub that persists across scenarios
- Cucumber does not have a WebMock auto-reset hook (webmock/minitest only wires Minitest teardown); per-scenario stub lifecycle is managed explicitly via instance variables on the World object

**Issues Resolved:**

- Prepend stub modules added test-only state to service classes, making test intent implicit and fragile — now all HTTP is intercepted at the network layer
- `config/environments/test.rb` loader caused stub state to persist even in test runs that didn't need it

**Issues Deferred:**

- `XAUTH-FUT-01`: `from_omniauth` Twitter lookup still uses `name` instead of `uid` — tracked in PROJECT.md Active list
- `HTTP-FUT-01`: optional helper module for repeated WebMock JSON fixtures (X v2, Mastodon API) — deferred; current duplication is acceptable

**Technical Debt Incurred:**

- None — this milestone reduced debt (removed 133 lines of prepend machinery)
