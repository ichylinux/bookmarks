# Roadmap snapshot: v1.19 — HTTP test stubs → WebMock

**Status:** Planning (opened 2026-05-14)  
**Phases:** 64–66 (continued from v1.18 Phase 63)

## Goal

Remove test-only prepend stub modules (`test/http_client_test_stubs.rb` + `config/environments/test.rb` loader) by standardizing on **WebMock** for full-stack and controller tests, while **keeping Faraday `:test`** for unit tests that already inject `connection:`.

## Phases

### Phase 64 — WebMock baseline

- Add `webmock` to Gemfile `:test`; bundle install.
- Configure in `test/test_helper.rb` (or `test/support/webmock.rb` required from there): disable real network by default; allow localhost / 127.0.0.1 / `::1` (and any Capybara/Selenium driver endpoints the project already uses).
- Smoke: `bin/rails test` still boots (no unintended global stub of internal requests).

**Maps to:** HTTP-01

**Success criteria:**

1. A new developer can run `bin/rails test` without hitting the public internet for Mastodon/X tests that will be migrated in Phase 65–66.
2. Documented allowlist is minimal and justified (comment or `CLAUDE.md`).

---

### Phase 65 — Minitest migration

- Rewrite `test/services/x_client_test.rb`, `test/services/mastodon_client_test.rb`, `test/controllers/x_accounts_controller_test.rb`, `test/controllers/mastodon_accounts_controller_test.rb` to stop using `stub_fetch_*` accessors.
- Prefer existing Faraday `:test` patterns for `MastodonClient` / `XClient` unit paths; use WebMock for cases that hit default connections (e.g. controller integration).
- OAuth1 (X): use flexible matchers (`hash_including`, regex body, or `stub_request` with block) so signatures do not brittle-match unless necessary.

**Maps to:** HTTP-02

**Success criteria:**

1. `bin/rails test` green with no references to removed stub accessors.
2. No require of `http_client_test_stubs.rb` from Minitest paths.

---

### Phase 66 — Cucumber + cleanup + docs

- Replace `XClient.stub_*` / `MastodonClient.stub_fetch_result` in `features/support/hooks.rb` with WebMock stubs in `Before`/`After` (or shared helper), aligned with scenario tags.
- Remove `require` from `config/environments/test.rb`; delete `test/http_client_test_stubs.rb`.
- Update `.planning/PROJECT.md` Key Decisions (supersede stub-accessor row); update `CLAUDE.md` if it documents the old stub pattern.
- Tri-suite: `yarn run lint`, `bin/rails test`, `bundle exec rake dad:test` (rerun Cucumber once on flake per policy).

**Maps to:** HTTP-03, HTTP-04, HTTP-05

**Success criteria:**

1. Cucumber green; no class-level stub accessors on `XClient` / `MastodonClient` anywhere in repo.
2. Tri-suite green; planning docs reflect the new testing contract.
