## v1.25 Requirements

### Data Layer

- [x] **COLW-01**: User's column width ratios persisted on `preferences` (JSON array of integers summing to 100, one entry per active column); model validates length matches `portal_column_count`, each value positive, sum = 100 — **Phase 80 ✓**
- [x] **COLW-02**: When no custom ratios stored (new user / migration default), desktop layout uses equal split (3×34/33/33 / 4×25%); changing `portal_column_count` normalizes width array length to equal split — **Phase 80 ✓**

### Preferences UI

- [x] **COLW-03**: Preferences page shows one ratio slider per column for current `portal_column_count` (3 or 4 sliders); sliders linked so ratios always sum to 100% before save — **Phase 81 ✓**
- [x] **COLW-04**: Submitting preferences form persists ratios; reloading page shows saved slider values; ja/en labels and help text present — **Phase 81 ✓**

### Portal Rendering (Desktop)

- [x] **COLW-05**: On desktop (`min-width: $portal-mobile-breakpoint`), welcome portal columns render at saved width ratios via `--portal-col-width-pct` CSS variable — **Phase 82 ✓**
- [x] **COLW-06**: Mobile portal layout unchanged: tab strip, one column visible at a time, `flex: 0 0 100%` per column — ratio preferences do not affect mobile viewport layout — **Phase 82 ✓**

### Safety & Tests

- [x] **COLW-07**: Downgrade/upgrade between 3 and 4 columns remains safe; width ratio UI and stored values stay consistent when column count changes — **Phase 82 ✓**
- [x] **COLW-08**: Minitest covers model validation, preferences save/reload, and welcome-page desktop markup for unequal 3- and 4-column examples; locale key parity for new strings — **Phase 83 ✓**
- [x] **COLW-09**: Tri-suite gate green at milestone close: `yarn run lint` ✓ · 416 Minitest 0 failures · 25 Cucumber 0 failed — **Phase 83 ✓**
