## Overview

Let users see which OAuth providers are linked to their account and disconnect individual ones from the preferences page. Introduces a dedicated `oauth_identities` table as the authoritative source for linked provider state, a `password_auth_enabled` flag for form auth, a disconnect controller with a safety guard, and a "Connected Accounts" section in preferences with bilingual (ja/en) labels and disconnect buttons.

## Milestone Summary

**Key Decisions:**
- `oauth_identities` unique index on `(user_id, provider)` — one row per provider per user; enforced at DB and model layers
- `password_auth_enabled` defaults to `false` — no existing users have set passwords via the reset flow
- Disconnect safety guard: blocked if no other linked provider AND `password_auth_enabled: false`
- No "connect new provider" from preferences — sign-in pages remain the only linking surface
- `OauthIdentity.upsert_for!` uses `find_or_initialize_by` + `save!` with `rescue RecordNotUnique; retry` for race safety
- `disconnect_form_auth!` uses `update_columns` to bypass callbacks atomically

**Issues Resolved:**
- Phase 114 code review: added `rescue/retry` for `RecordNotUnique`, inline AR classes in backfill, `(provider, uid)` unique index
- Phases 115–118 implemented before autonomous workflow ran; retroactive planning artifacts created
