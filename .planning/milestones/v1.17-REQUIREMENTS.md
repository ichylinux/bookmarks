# Requirements Archive: v1.17 Email Registration for X/Twitter Users

**Status:** ✅ SHIPPED (archived 2026-05-13)  
**Milestone:** v1.17  
**Source:** `.planning/REQUIREMENTS.md` at milestone close (checkboxes normalized to shipped state).

---

## Milestone Goal

Allow users who signed up via X/Twitter (dummy email) to register a real email address so they can use Google OAuth against the same account, with collision-safe updates and ja/en UI from preferences.

---

## v1.17 Requirements (final)

### Email Registration (EMAIL)

- [x] **EMAIL-01**: Devise `:validatable` format and uniqueness on the email update path, plus custom dummy-pattern rejection `on: :update` — implemented in `User` and covered by `user_test.rb`.

### Controller & Route (CTRL)

- [x] **CTRL-01**: Dummy-email user can register a real email via `Users::EmailRegistrationsController` `new` / `create`.
- [x] **CTRL-02**: Clear error when email is already taken; `RecordNotUnique` rescued to friendly re-render.
- [x] **CTRL-03**: Real-email users redirected away from registration form (`has_valid_email?` guard).

### View & UX (VIEW)

- [x] **VIEW-01**: Preferences shows email registration entry only when `!has_valid_email?`.
- [x] **VIEW-02**: Localized success flash after successful registration.

### Locale & Tests (I18N / TEST)

- [x] **I18N-01**: ja/en keys for form, preferences row, flash, AR dummy message — parity tests.
- [x] **TEST-01**: Minitest covers model paths, controller guards, collision, preferences link visibility, ja/en flashes.
