# Milestone v1.31: X Account Manual Add (Non-Following)

**Status:** ✅ SHIPPED 2026-05-22
**Phases:** 104–108
**Total Plans:** 6

## Overview

Allow users to add any public X account to their `/x_accounts` dashboard by entering a handle (`@xxxx`), complementing the existing follow-based discovery flow. Manually-added accounts survive the refresh soft-delete sweep, carry a visual badge, and are covered by Cucumber E2E scenarios.

## Phases

### Phase 104: Schema, Model & Refresh Guard

**Goal:** `manually_added` boolean column migration + `upsert_manual!` + refresh soft-delete protection
**Depends on:** (none)
**Plans:** 2 plans

Plans:
- [x] 104-01: Add `manually_added boolean NOT NULL DEFAULT false` to `x_accounts` via additive Rails migration
- [x] 104-02: Add `XAccount.upsert_manual!` (idempotent create/restore) + `next if acc.manually_added?` guard in refresh soft-delete loop + 4 Minitest cases

**Details:**
- Migration: `db/migrate/20260522000001_add_manually_added_to_x_accounts.rb` — additive, no index (low-cardinality boolean, queries are user-scoped)
- `upsert_manual!`: `first_or_initialize on (user_id, x_user_id)`; unconditionally sets `manually_added: true, deleted: false`; no selection side-effect
- Refresh guard: `next if acc.manually_added?` immediately after `next if seen[acc.x_user_id]`; `assign_attributes` in refresh upsert loop does NOT include `manually_added:` to preserve flag on overlap rows

## Milestone Summary

**Key Decisions:**
- `upsert_manual!` uses `first_or_initialize` on `(user_id, x_user_id)` — unconditional set preserves idempotency on restore
- `assign_attributes` in refresh loop explicitly excludes `manually_added:` — prevents flag overwrite on follow-overlap rows
- Blank input guard in controller (not service) — cleaner separation; saves API round-trip
- Already-active check before upsert — distinguishes "add" vs "restore" for flash messaging
- WebMock lookup stubs use regex (not exact URL strings) — `XClient` appends `?user.fields=...` query param
- `lookup_user_by_username` routes via `following_connection(user)` — honours `@forced_connection` for Faraday `:test` injection in Minitest

**Issues Resolved:**
- `lookup_user_by_username` lacked username format validation before URL interpolation (CR-01 fix)
- `parse_lookup_response` missing `401` branch — would fall through to `:api_error` instead of `:unauthorized` (WR-02 fix)
- `:timeout` and `:network` error symbols not distinguished in rescue chain (WR-03 fix)
- WebMock exact URL stubs rejected requests with query params — switched to regex (Phase 108 fix)

**Issues Deferred:**
- XMAN-FUT-01: Total cap on manually-added accounts
- XMAN-FUT-02: Bulk add by handle list
- XMAN-FUT-03: Dedicated remove action for manually-added accounts
