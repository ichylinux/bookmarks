## v1 Requirements (Final Status)

### Mobile Lazy Loading

- [x] **LAZY-01**: On mobile (≤768px), only gadgets in the initially active column are AJAX-loaded on page load — **Delivered: Phase 76**
- [x] **LAZY-02**: When the user switches to a new column tab, that column's gadgets are loaded on first visit — **Delivered: Phase 76+77**
- [x] **LAZY-03**: Revisiting an already-loaded column does not trigger another AJAX request — **Delivered: Phase 76**
- [x] **LAZY-04**: Load state resets on each page load — gadgets reload fresh on explicit page refresh — **Delivered: Phase 76** (closure scoping)

### Desktop Compatibility

- [x] **DESKTP-01**: Desktop behavior is unchanged — all gadgets in all columns load on page load as today — **Delivered: Phase 76** (register desktop pass-through)
- [x] **DESKTP-02**: Feature works correctly across all themes (modern/classic/simple) and both column counts (3 and 4) — **Delivered: Phase 76** (theme-agnostic design)

### Implementation Contract

- [x] **IMPL-01**: A new `portal_lazy.js` coordinator module exposes `window.portalLazy` with `register(columnIndex, loadFn)` and `loadColumn(index)` API — **Delivered: Phase 76**
- [x] **IMPL-02**: All AJAX gadget partials (`_feed`, `_mastodon_account`, `_x_account`, `_calendar_gadget`) register with the coordinator instead of firing unconditionally on `$(document).ready` on mobile — **Delivered: Phase 77**
- [x] **IMPL-03**: `activateColumn()` in `portal_mobile_tabs.js` triggers `portalLazy.loadColumn(index)` — covering tab-click, swipe, and localStorage-restore activation paths — **Delivered: Phase 77**
- [x] **IMPL-04**: Load state is marked synchronously before any `$.get` fires, preventing duplicate in-flight requests on rapid tab switching — **Delivered: Phase 76+77+79**

## Out of Scope

| Feature | Reason |
|---------|--------|
| Server-side lazy rendering (only render active column HTML) | No server changes needed; all gadget HTML is already rendered SSR; only AJAX fetches are deferred |
| Prefetching adjacent columns | Adds complexity; contradicts the "load only on first visit" contract |
| Persisting loaded state across page loads (localStorage) | Defeats the "reload = fresh" contract; session memory only |
| Cancelling in-flight requests on fast tab switch | Complexity not justified; load-state marked synchronously prevents duplicate requests |
| Showing loading indicators per-column | No UI change needed; existing per-gadget loading state is sufficient |
| Sorting/reordering gadgets on mobile | Separate concern; `$.sortable` mobile guard is a safety fix, not a sort feature |
