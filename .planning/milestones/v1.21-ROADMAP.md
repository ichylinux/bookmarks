# Milestone v1.21: X Gadget Tweet Count Preference

**Status:** ✅ SHIPPED 2026-05-16
**Phases:** 69
**Total Plans:** 1

## Overview

Adds per-account tweet display count preference to the X gadget. Users can configure how many tweets are shown per X account from the `/x_accounts` management page. The count is stored on the `x_accounts` row (not a global preference) and honoured by the welcome-page X gadget via `XClient#fetch_recent_tweets`.

## Milestone Summary

**Key Decisions:**
- `before_save` `set_display_count_default` fires after validation; the callback is a nil-guard only since validation already blocks values ≤ 0. DB default of 5 handles the practical nil case.
- XClient `fetch_recent_tweets` requests `max(limit, 5)` from the X API (API minimum is 5) then slices result to the user's preference. This fixes the API error when `display_count < 5` without changing the UX.

**Issues Resolved:**
- X API v2 `max_results` must be ≥ 5; passing `display_count=3` caused `api_error`. Fixed with `api_lim = [lim, 5].max` + `items.first(lim)`.

**Issues Deferred:**
- XCNT-FUT-01: No upper-bound validation on display_count (API allows up to 100; model only enforces > 0). Pre-existing pattern shared with Feed/MastodonAccount.
- XAUTH-FUT-01: `from_omniauth` Twitter branch still looks up by `name`; switch to `uid` deferred to v1.22+.

**Technical Debt Incurred:**
- None significant. Debug logging lines removed from controller before milestone close.
