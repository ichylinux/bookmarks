## Milestone Goal

Twitter-linked users (those whose OAuth 1.0a credentials are persisted from a Twitter sign-in) can pick from their X following list to display selected accounts' latest tweets as welcome-page gadgets — mirroring the v1.16 Mastodon pattern with OAuth 1.0a User Context auth and a DB-cached following list. Read-only end-to-end: no posting, liking, or following changes. Tests run entirely against `XClient` stubs; ja/en parity is enforced across every new surface.

## Phase 60: User OAuth Token Persistence

**Goal:** `User.from_omniauth` Twitter branch persists `provider`, `uid`, `token`, and `token_secret` on both the create and the re-auth find branches (token rotation), with `token`/`token_secret` encrypted at rest. `require_twitter_linked` gates the upcoming X surfaces on `uid + token` (never `name`), and drawer / preferences entry-link visibility uses the same predicate.

**Depends on:** Nothing (first phase of v1.18; v1.17 shipped)  
**Requirements:** XAUTH-01, XAUTH-02, XAUTH-03, XAUTH-04, XTEST-01  
**Locale slice (under XI18N-01, enforced in Phase 63):** `x_accounts.errors.not_linked` alert key + drawer/preferences entry-link label keys for X Accounts.

**Success criteria:**

1. Twitter `from_omniauth` flow persists `provider`, `uid`, `token`, `token_secret` on a newly created user; a re-auth on an existing Twitter user updates the same four fields (token rotation observable on `user.reload`).
2. `users.token_secret` column exists (string, nullable); `User` model declares `encrypts :token, :token_secret`. A model test asserts the stored column value differs from the plaintext token (encrypted-at-rest contract).
3. `require_twitter_linked` redirects to `preferences_path` with a localized alert when `current_user.uid.blank?` or `current_user.token.blank?`, regardless of whether `current_user.name` is set. (`users.name` is intentionally NOT in the gate.)
4. Drawer navigation and preferences entry-link for X Accounts render only when `current_user.uid.present? && current_user.token.present?`; hidden for Google-only users and for pre-v1.18 Twitter users who have not yet re-authed.
5. Tri-suite green at phase end: `yarn run lint`, `bin/rails test`, `bundle exec rake dad:test`.

## Phase 61: XClient Service + Stub Contract

**Goal:** A new `app/services/x_client.rb` exposes `fetch_following(user:)` and `fetch_recent_tweets(x_user_id:, limit:)` over Faraday + `faraday-oauth1` middleware with explicit connect/read timeouts, a uniform `{ success:, items:|error: }` return shape (with `:unauthorized` and `:rate_limited` added on top of `MastodonClient`'s error set), and two class-level `stub_fetch_*_result` accessors that short-circuit the public methods in tests.

**Depends on:** Phase 60 (consumes persisted `user.token` / `user.token_secret`)  
**Requirements:** XAPI-01, XAPI-02, XAPI-03, XAPI-04, XAPI-05, XTEST-02  
**Locale slice:** None (no user-visible surface introduced; error symbols are surfaced by callers in later phases).

**Success criteria:**

1. `XClient#fetch_following(user:)` and `#fetch_recent_tweets(x_user_id:, limit:)` return `{ success: true, items: [...] }` on stubbed 200 responses; following pagination cycles via request `pagination_token` ↔ response `meta.next_token`; `max_results` is clamped to `[requested, 5].max.clamp(5, 100)`; tweet calls send `?exclude=retweets,replies`.
2. All error symbols (`:timeout, :network, :not_found, :api_error, :parse_error, :unauthorized, :rate_limited`) are produced from the matching Faraday `:test` adapter failure modes; covered by Minitest one branch each.
3. `XClient.stub_fetch_following_result =` and `XClient.stub_fetch_tweets_result =` short-circuit the public methods to return the supplied hash (normalized to a Hash with `with_indifferent_access`; malformed input falls back to `{ success: false, error: :api_error }`); both accessors are cleared in Minitest `setup`/`teardown`.
4. Tweet text normalization: `entities.urls[].display_url` substitution for `t.co` shortlinks runs before truncation to `PREVIEW_LENGTH = 100`; the latest tweet id resolved as the last element of `edit_history_tweet_ids` is what `XClient` emits.
5. One integration-style test builds a real (non-`:test`) Faraday connection with the OAuth1 middleware and asserts the outgoing `Authorization` header begins with `OAuth oauth_consumer_key=` (PITFALL-1A guard). Tri-suite green.

## Phase 62: x_accounts Model + Management UI + Refresh Diff

**Goal:** Introduce the `x_accounts` cache table and `XAccount` model (`Crud::ByUser`, `gadget_id`, derived `profile_url`), plus `/x_accounts` management page with refresh, per-row selection, protected-account confirmation toggle, 12-cap (soft warning at 9), and a "last refreshed at" timestamp. Refresh runs `XClient#fetch_following` and diff-upserts the user's cache. All new surface ships fully localized in ja/en.

**Depends on:** Phase 61 (calls `XClient#fetch_following`)  
**Requirements:** XACCT-01, XACCT-02, XACCT-03, XACCT-04, XACCT-05, XACCT-06, XACCT-07, XACCT-08, XTEST-03  
**Locale slice (under XI18N-01, enforced in Phase 63):** `x_accounts.*` — index page chrome, refresh button, refresh outcome flashes, last-refreshed label, selection cap warning + error, protected confirmation copy, preferences entry-link label.

**Success criteria:**

1. `/x_accounts` index renders the user's cached following entries (avatar, display name, `@handle`) with a per-row select checkbox; controller `before_action :require_twitter_linked` enforces the Phase 60 gate, and the preferences page entry-link uses the same predicate (XACCT-08).
2. POST `/x_accounts/refresh` calls `XClient#fetch_following` and diff-upserts: new rows inserted, existing rows updated, rows missing-from-response soft-deleted when `selected: true` (preserves the user's pin) and hard-deleted otherwise, previously soft-deleted rows un-soft-deleted on reappearance. Last refresh timestamp is displayed above the table as "最終更新: YYYY-MM-DD HH:MM" / "Last refreshed: …".
3. PATCH `/x_accounts/:id` toggles `selected: true/false`; total `selected: true` rows per user are hard-capped at 12 (13th returns localized error); a soft warning is shown when the selected count reaches 9; rows with `protected: true` require `protected_acknowledged: true` to be set before they can be marked `selected: true`; server rejects toggling `selected=true` on rows not owned by `current_user`.
4. New keys exist under `x_accounts.*` in both `ja.yml` and `en.yml`; the existing locale parity test still passes after the phase ships (parity itself is gated formally in Phase 63 across all phases' keys).
5. Minitest covers model URL/derivation, cap enforcement, protected-confirmation guard, all five refresh-diff branches (insert / update / soft-delete / hard-delete / un-soft-delete), and per-user ownership rejection. Tri-suite green.

## Phase 63: Welcome Gadget + Show Action + Tri-Suite Gate

**Goal:** Selected X accounts render as one-AJAX-gadget-each panels on the welcome page through `Portal#get_gadgets`; `XAccountsController#show` answers HTML + XHR via `render layout: !request.xhr?` and fetches up to `display_count` recent tweets via `XClient#fetch_recent_tweets`. Per-error-symbol localized empty/error states (including a re-sign-in CTA on `:unauthorized`). Cucumber `features/06.X.feature` with `@x_gadget` Before/After hooks plus a global Before hook for state isolation. ja/en parity across every new key shipped across Phases 60/62/63 is enforced by the existing parity test, closing XI18N-01..03. Final tri-suite gate.

**Depends on:** Phase 62 (selection rows must exist) and Phase 61 (service must be stub-callable)  
**Requirements:** XGAD-01, XGAD-02, XGAD-03, XGAD-04, XGAD-05, XI18N-01, XI18N-02, XI18N-03, XTEST-04, XTEST-05, XTEST-06  
**Locale slice (closes XI18N-01):** `welcome.x_account.*` (gadget title, empty state, loading state) and shared `errors.x_client.*` (per-error-symbol gadget states, with the `:unauthorized` re-sign-in CTA label).

**Success criteria:**

1. A signed-in Twitter-linked user with at least one `selected: true, deleted: false` `x_account` sees a corresponding gadget panel on `/` rendered through `Portal#get_gadgets`; the panel loads its tweet list via XHR to `XAccountsController#show`, which uses `render layout: !request.xhr?`.
2. Each tweet preview is a stripped, t.co-expanded, truncated one-liner (`PREVIEW_LENGTH = 100`) linked to `https://x.com/i/status/{latest_tweet_id}` (URL constructed server-side, never echoed from `entities.urls[].url`); click target honors `current_user.preference.open_links_in_new_tab?`; tweet text and display name are never `raw`/`html_safe` (XGAD-05).
3. Per-error-symbol localized empty/error states render under all seven `XClient` failures (`:timeout / :network / :not_found / :api_error / :parse_error / :unauthorized / :rate_limited`); `:unauthorized` includes a re-sign-in CTA pointing to `/users/auth/twitter`.
4. Cucumber `features/06.X.feature` (`@x_gadget` Before/After hooks install/clear `XClient.stub_fetch_*_result`; a global Before hook clears `XAccount.where(user_id: fixture_user.id).delete_all`, both stub accessors, and resets `token` / `token_secret` / `uid` where appropriate) verifies the welcome gadget end-to-end — Twitter-linked fixture user sees the panel, sees at least one stubbed tweet preview, and the click-through URL matches `https://x.com/i/status/...`. User-generated content (tweet text, display name, `@handle`) is rendered untranslated (XI18N-03).
5. Final tri-suite gate green (XTEST-06): `yarn run lint`, `bin/rails test`, `bundle exec rake dad:test`. ja/en key parity is enforced across every new key shipped in Phases 60, 62, and 63 (`x_accounts.*`, `welcome.x_account.*`, shared `errors.x_client.*`) by the existing parity test — closes XI18N-01 (umbrella) and XI18N-02 (parity).

## Notes

- Phase numbering continues from v1.17 (Phase 59 was the last shipped phase).
- Patterns reused from v1.16 Mastodon: `Crud::ByUser`, `Portal#get_gadgets`, AJAX `show` with `render layout: !request.xhr?`, `stub_fetch_result`-shaped class accessors, Faraday `:test` adapter, Cucumber feature stub hooks, ja/en parity test.
- **3 user decisions baked in:**
  - **Q8 = 1** — Reuse existing dead columns `users.{provider, uid, token}` and add only `users.token_secret`. `encrypts :token, :token_secret` on `User`.
  - **Q9 = 1** — Selection hard-cap = 12; soft warning surfaces at 9 selected.
  - **Q10 = 1** — Protected (private) accounts default to off; per-account `protected_acknowledged` confirmation toggle on the management page before they can be selected.
- **Cross-cutting REQ-ID assignment:** XI18N-01 / XI18N-02 / XI18N-03 are all enforced end-to-end in Phase 63 (the final phase to add keys and the home of the parity test sweep + welcome scenario), even though their *slices* ship in Phases 60 and 62 — captured per-phase under "Locale slice" so the planning artifact stays honest about where keys originate.
- **XTEST distribution:** XTEST-01..03 land in the phases that introduce their respective surfaces (60: user_test for OAuth persistence; 61: XClient minitest; 62: model + controller minitest). XTEST-04..06 live in Phase 63 alongside the Cucumber surface they verify — this honors `CLAUDE.md`'s policy against a dedicated "tests phase."
- **Open carry-forward NOT addressed in v1.18:** PITFALL-02 (the `from_omniauth` Twitter branch's name-keyed lookup → uid-keyed lookup switch) — Phase 60 lays the prerequisite (`users.uid` now persisted), but flipping `find_by(name:)` → `find_by(uid:)` is deferred to v1.19+ because it touches identity semantics for pre-v1.18 users. Tracked as XAUTH-FUT-01 in `REQUIREMENTS.md`.
- **Cucumber flake policy** (`CLAUDE.md`): the global Before hook addition in Phase 63 (`XAccount.where(user_id:).delete_all` + both stub accessors + token reset) is the contract that prevents scenario-order leakage on the new surface. Pre-existing flakes remain re-run-once eligible per project policy.
