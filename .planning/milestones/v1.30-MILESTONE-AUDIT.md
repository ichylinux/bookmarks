## Evidence Summary

All 6 requirements confirmed delivered via codebase inspection:

### USR-01 — Route & Gate
- `config/routes.rb`: `namespace :admin { resources :users, only: [:index] }` → `GET /admin/users`
- `Admin::UsersController < Admin::BaseController`; `Admin::BaseController#require_admin` → `head :not_found unless current_user&.admin?`
- `ApplicationController#authenticate_user!` fires first for guests → redirect to `new_user_session_path`
- Minitest: 3 access-control scenarios pass (528 total, 0 failures)

### USR-02 — 7-Column Table + Soft-Deleted Visibility
- View: `@users.each` renders all 7 columns (id, email, x_user_name, admin_flag, last_sign_in_at, created_at, updated_at)
- `User.all` (not `User.active`) confirms soft-deleted rows included
- Controller: `User.all.includes(:x_accounts).order(:id)` — N+1 prevention via eager load
- Minitest: soft-deleted visibility test + column count assertion pass

### USR-03 — x_user_name
- View: `user.x_accounts.reject(&:deleted?).sort_by(&:id).first&.username`
- `deleted?` auto-generated from `x_accounts.deleted` boolean column
- In-memory filter on preloaded association — no N+1
- Minitest: blank fallback test (`users(:three)` has no XAccount) passes

### USR-04 — admin_flag
- View: `user.admin? ? '✓' : '—'`
- `admin?` auto-generated from `users.admin` boolean column
- Minitest: both ✓ and — indicators asserted in same test

### USR-05 — Nav Link
- `_nav_sections.html.erb`: admin section with `admin_users_path` before `admin_x_api_usages_path`, guarded by `current_user.admin?`
- Cucumber: admin navigates to user list (31/31 passed)

### USR-06 — Locale Keys + Parity Test
- `ja.yml` + `en.yml`: 9 keys each (`nav.users` + 8 `admin.users.index.*`)
- View uses `t('.title')` / `t('.col_*')` (relative keys, resolve correctly for `admin/users/index`)
- `test/i18n/admin_users_i18n_test.rb`: 2 parity tests (ja + en), all 9 keys verified
- Minitest: `admin.users.index.title` asserted in access-control test (locale: :ja)
