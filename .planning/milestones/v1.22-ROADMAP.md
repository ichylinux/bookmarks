# Milestone v1.22: Landing at Root

**Status:** ✅ SHIPPED 2026-05-17
**Phases:** 70–72
**Total Plans:** 3

## Overview

Moved the landing page inline to `/` (no redirect), removed the separate `/landing` route and `LandingController`, fixed the deferred Twitter `from_omniauth` uid lookup bug, and updated all test contracts to reflect the new routing behavior.

## Milestone Summary

**Key Decisions:**

- Inline landing content moved to `WelcomeController#index` (guest branch) rather than a separate controller; `LandingController` deleted entirely — simplifies routing without introducing a new abstraction
- `from_omniauth` Twitter uid fix is independent of the routing refactor — kept as a parallel phase (72) with no coupling to 70–71
- No `/landing` redirect fallback for old-link compatibility — personal app with direct sign-in links; breaking the URL is intentional and documented

**Issues Resolved:**

- Twitter OAuth `from_omniauth` name-based lookup bug (deferred from v1.18 as XAUTH-FUT-01) — closed in Phase 72
- `/landing` route removed without a redirect — old bookmarks to `/landing` now return routing error

**Issues Deferred:**

- Per-user landing conversion analytics (decide if `/landing` removal changes tracking) — deferred to future milestone
- Public SEO/meta tags on `/` for unauthenticated visitors — deferred to future milestone

**Technical Debt Incurred:**

- No `.planning/phases/` directories created for Phases 70–72 (milestone executed without standard GSD phase artifacts); traceability via git commits, ROADMAP.md success criteria, and REQUIREMENTS archive
