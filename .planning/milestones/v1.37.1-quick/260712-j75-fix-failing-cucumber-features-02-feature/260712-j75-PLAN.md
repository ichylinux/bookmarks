## 根本原因（潜在的な間欠失敗の原因）

`0abf30e` は「タッチ端末は `hover: none` / `pointer: coarse` を報告する」前提に依存している。しかし **`dad:test` のヘッドレス Chrome は、幅を 390px（モバイル）にリサイズしても `hover: hover` / `pointer: fine` を報告し続ける**（`hover`/`pointer` メディア特性はビューポート幅ではなく入力デバイス種別で決まるため）。したがってテスト環境では `@media (hover: hover) and (pointer: fine)` が **依然マッチ** し、`div.title:hover .todo-gadget-new-link { opacity: 1 }` が生きている。

さらに Capybara/Selenium はシナリオ間でブラウザセッション（＝マウス座標）を再利用する。完了リンク（`div.title` 内）クリック後や前シナリオからのカーソル位置により `div.title:hover` が成立すると、`.todo-gadget-new-link` が `opacity: 1` になり、最終ステップ `assert has_no_selector?('.todo-gadget-new-link', visible: true)` が失敗しうる。現状 green なのは「Selenium が `opacity: 0` を非表示扱いする」ことと「:hover が毎回は持続しない」ことに依存しており、脆い。

## 修正方針（最小・防御的・CSS のみ）

モバイル幅では「追加」の可視性を `.title--gadget-actions-visible` だけに束ねる。`@media (max-width: 767px)` 内に、`:hover` 規則より高い詳細度で `opacity: 0` を固定する規則を 1 つ追加する:

- 追加規則 `.gadget.todo .title--gadget-with-icon .todo-gadget-new-link { opacity: 0; }` の詳細度は (0,4,0)。
- `:hover` 規則 `div.title:hover .todo-gadget-new-link` は (0,3,1) → 追加規則が上書きし、hover でも表示されない。
- 表示規則 `.gadget.todo .title--gadget-with-icon.title--gadget-actions-visible .todo-gadget-new-link { opacity: 1 }` は (0,5,0) → タップ表示は維持される。

既存の `pointer-events: none` 規則・`.title--gadget-actions-visible` 表示規則・`@media (hover: hover) and (pointer: fine)` 規則・JS・ビューは変更しない。デスクトップ（幅 > 767px）はこの `@media` 外なので影響なし。既存の CSS 契約テストも既存セレクタを変えないため壊れない。
