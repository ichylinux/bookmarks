<objective>
Integrate the note panel into the mobile portal swipe cycle with circular (wrap-around) swiping, on ALL themes that render the portal + note panel.

Today the mobile swipe engine (`portal_mobile_tabs.js`) only cycles `.portal-column` elements and CLAMPS at the ends (`Math.min(Math.max(...))`). The note panel (`#notes-tab-panel`) lives OUTSIDE `.portal` and is only reachable via a full page reload (`root_path(tab:'notes')`). The client-side reveal logic exists but is locked behind `body.simple` in `notes_tabs.js`, and the welcome/drawer themes use a separate inline `$.get` loader in `_dashboard.html.erb`.

This plan:
1. Promotes the note-reveal logic into a single theme-agnostic module (`window.notePane`) reused by every code path, so swipe and tab/query paths share ONE reveal implementation and never fight (no double gadget load, correct hidden-class per theme).
2. Replaces clamping with modular wrap-around arithmetic over an ordered pane cycle `[col 0 … col N-1, (note pane IF available)]`, wrapping circularly in both directions, with note pane included only when `use_note` is enabled.
3. Persists/restores the active pane (column index OR note sentinel) and keeps the `_dashboard.html.erb` prehydrate script consistent.

Purpose: One coherent mobile navigation model — every portal pane plus the note is reachable by swiping, client-side, on every theme.
Output: Updated `notes_tabs.js`, `portal_mobile_tabs.js`, and `_dashboard.html.erb`; full green-bar gate (lint + minitest + cucumber) and a human swipe verification.
</objective>

Cycle model:
- `colCount = portalColumnCount($portal)`; `noteInCycle = (typeof window.notePane !== 'undefined') && window.notePane.available()`; `cycleLength = colCount + (noteInCycle ? 1 : 0)`. The note sentinel index is `colCount` (the last slot).
- Replace the `if (colCount < 2) return;` guard with `if (cycleLength < 2) return;` so 1 column + note is still swipeable.
- Determine `currentIndex`: if `window.notePane` exists and `notePane.isVisible()` → `currentIndex = colCount` (note sentinel); else use the existing column-derivation (active `.portal-column-tab` index, or `parseActiveColumnIndexFromPortal`).
- `direction = totalDx < 0 ? 1 : -1` (forward = swipe left). Compute `newIndex = ((currentIndex + direction) % cycleLength + cycleLength) % cycleLength` (modular wrap-around — REMOVE the `Math.min(Math.max(...))` clamp).
- Apply newIndex:
  - If `noteInCycle && newIndex === colCount` (note sentinel): call `window.notePane.show()`, deactivate all `.portal-column-tab` (no column active: remove `--active`, set `aria-selected=false`), and persist the note sentinel to localStorage `portalMobileActiveColumn` as the string `'note'`. Do NOT call `activateColumn` (it would overwrite the sentinel with a column index).
  - Else (a column): if `window.notePane` exists call `window.notePane.hide()` to ensure the home/portal panel is visible, then `activateColumn($portal, $tabs, newIndex)` (which re-persists the numeric column index).
- Note: when restoring/hiding columns, ensure the note panel is hidden first (via `notePane.hide()`) before activating the column so the portal panel is visible.

Persistence + restore (bottom init block, currently lines ~133-148):
- The localStorage value may now be the string `'note'` OR a numeric column index. On restore, read raw; if `raw === 'note'` and `noteInCycle` → `window.notePane.show()` and deactivate column tabs (do NOT activateColumn). Otherwise parse the int and use the existing column-restore logic (default to column 0 when NaN/out of range).
- Keep the column tab-click handler unchanged for column selection, but it should also call `window.notePane.hide()` (when notePane exists) before/within activating a column so clicking a column tab leaves the note pane.

Prehydrate consistency in `app/views/welcome/_dashboard.html.erb`: the prehydrate IIFE reads `portalMobileActiveColumn` and sets `--portal-initial-active-index`. With the `'note'` sentinel, `Number.parseInt('note',10)` is NaN and the existing `if (Number.isNaN(restored) || restored < 0) return;` guard already no-ops correctly (no bogus column index forced) — confirm this still holds and add a short comment noting `'note'` is a valid stored sentinel handled by the NaN guard. Make no other prehydrate change; a brief reveal of the home panel before JS shows the note pane on reload is acceptable for this quick task.
