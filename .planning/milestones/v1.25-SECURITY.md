# Security Verification: Milestone v1.25 (Portal Column Width Ratios)

## Threat Model Review

The threat model for Milestone v1.25 focuses on input validation of user-controlled layout preferences and ensuring cross-user data isolation.

| Threat ID | Category | Component | Mitigation Plan | Status |
|-----------|----------|-----------|-----------------|--------|
| T-25-01 | Tampering | Preference Model | Strict validation of `portal_column_widths` (integers, length, sum=100) | **VERIFIED** |
| T-25-02 | Information Disclosure | PreferencesController | Scoped access via `current_user.id` | **VERIFIED** |
| T-25-03 | XSS | Welcome Portal View | Data casting to Integer + `tag.attributes` escaping | **VERIFIED** |
| T-25-SC | Tampering | Supply Chain | No new external dependencies introduced | **VERIFIED** |

## Verification Details

### T-25-01: Invalid Portal Widths (Tampering)
- **Code:** `app/models/preference.rb` implements `cast_portal_column_widths` to force values to integers via `to_i`, and `widths_valid_for_count?` to enforce structural integrity.
  ```ruby
  def widths_valid_for_count?(widths, count)
    return false unless widths.is_a?(Array)
    return false unless widths.length == count
    return false unless widths.all? { |width| width.is_a?(Integer) && width.positive? }
    return false unless widths.sum == 100
    true
  end
  ```
- **Test:** `test_portal_column_widthsは合計100で列数と一致する必要がある` and `test_列数と幅配列の長さが不一致のとき均等分割に正規化される` in `test/models/preference_test.rb` verify that invalid inputs are rejected or normalized.

### T-25-02: Cross-User Preference Access (Information Disclosure)
- **Code:** `PreferencesController` always finds the user via `current_user.id`, preventing attackers from modifying other users' preferences by guessing IDs.
  ```ruby
  def update
    @user = User.find(current_user.id)
    # ...
  end
  ```
- **Note:** Rails' `accepts_nested_attributes_for` further ensures that the nested `preference` record must belong to the `@user` record being updated.

### T-25-03: Portal Width Style Injection (XSS)
- **Code:** `app/views/welcome/_portal_column_section.html.erb` uses the validated integer values in a CSS variable.
  ```erb
  <% col_width_style = portal_column_widths&.at(i) ? "--portal-col-width-pct: #{portal_column_widths[i]}%;" : nil %>
  <%= tag.attributes(style: col_width_style) if col_width_style %>
  ```
- **Verification:** Since the `Preference` model casts values to integers, any malicious string (e.g., `10%; color: red;`) is reduced to an integer (e.g., `10`) before reaching the view, neutralizing any style injection attempts.

### T-25-SC: Supply Chain Integrity
- **Audit:** Verified via `git show --stat` that no changes were made to `Gemfile`, `Gemfile.lock`, `package.json`, or `yarn.lock` during this milestone.

## Conclusion

The security posture for Milestone v1.25 is robust. Input validation at the model layer prevents malformed or malicious layout data from persisting, and the controller ensures strict multi-tenancy. No new security surface was introduced via external dependencies.
